description: Реализовать фичу по tasks.md — оркестрирует developer (по задачам, TDD) → tester (сверка acceptance criteria) → reviewer (gate перед финальным /commit)
argument-hint: [конкретные ID задач через запятую — необязательно, иначе все незакрытые]
---

**ID задач от пользователя (необязательно):** $ARGUMENTS

Это самая длинная и рискованная команда цикла — веди её по шагам явно, не сокращай.

## 0. Предусловия

1. Определи текущую ветку (`git branch --show-current`) — должна быть `feature/NNN-*`, совпадающая с `tasks.md`, который собираешься выполнять. Эта команда НЕ создаёт новую ветку — она уже создана в `/specify`.
2. Найди `specs/NNN-feature-name/{spec.md,plan.md,tasks.md}`. Если чего-то нет — сообщи, какой фазы не хватает, и останови выполнение.

## 1. Цикл developer (по фазам)

Если пользователь передал конкретные ID задач в `$ARGUMENTS` — обработай только их одним проходом (без разбиения по фазам, шаг батчинга ниже всё равно применяй среди них) и закоммить один раз по завершении; иначе иди по `tasks.md` **по фазам** (Setup → Tests → Core → Integration → Polish) в этом порядке:

Для каждой фазы:

1. Раздели незакрытые задачи фазы на группы для вызовов `developer`: подряд идущие задачи, помеченные `[P]` (реально независимые), объединяй в одну группу — один вызов `developer` на группу. Задачи без `[P]` — отдельная группа из одной задачи каждая. Порядок групп внутри фазы — как в `tasks.md`.
2. Для каждой группы — спавни subagent `developer` (Agent tool, `subagent_type: "developer"`, foreground) с самодостаточным prompt: все `T00N` группы с текстом задач и связанными `AC-N` из `spec.md`, их строки «Контекст:» из `tasks.md` (если есть), пути к `plan.md` и `.specify/memory/constitution.md`.
3. `developer` не может спрашивать пользователя напрямую — если в его ответе есть блок `## ВОПРОСЫ ПОЛЬЗОВАТЕЛЮ`, часть группы ещё не доделана. Задай эти вопросы через `AskUserQuestion` в основном потоке, затем через `SendMessage` верни ответы тому же вызову `developer`, чтобы он доделал оставшуюся задачу группы. Повтори при необходимости.
4. После каждой группы — прогони `git status`/`git diff --stat`, коротко проверь, что чек-боксы завершённых `T00N` в `tasks.md` отмечены и тесты, судя по выводу агента, зелёные.
5. Когда все группы фазы обработаны — один раз `/commit` с аргументом «только закоммить, не мержи и не пушь» (если есть изменения в рабочем дереве). Не коммить после каждой группы/задачи внутри фазы.

## 2. tester (после того как все задачи закрыты)

1. Спавни subagent `tester` (Agent tool, `subagent_type: "tester"`, foreground) с prompt: полный `spec.md` (все `AC-N`), путь к коду фичи.
2. `tester` не может спрашивать пользователя напрямую — если в его ответе есть блок `## ВОПРОСЫ ПОЛЬЗОВАТЕЛЮ` (неоднозначная формулировка `AC-N`), задай эти вопросы через `AskUserQuestion` в основном потоке, затем через `SendMessage` верни ответы тому же вызову `tester`, чтобы он довёл проверку до конца. Повтори при необходимости.
3. Прочитай итоговую таблицу `AC-N` → статус.
   - Все `AC-N` пройдены → переходи к шагу 4.
   - Есть непройденные → покажи отчёт пользователю. Если проблема в коде — верни конкретную задачу `developer` на доработку (раздел 1 для этой одной задачи) и прогони `tester` заново. Если проблема в том, что `tasks.md` не покрывает `AC-N` вообще — сообщи пользователю, что нужен возврат к `/tasks`, и остановись (это не чинится внутри `/implement`).
   - **Ограничение:** не более 2 циклов «tester → доработка» подряд без участия пользователя. На третьем несовпадении — остановись и спроси пользователя явно, как поступить.
4. `/commit` с аргументом «только закоммить, не мержи и не пушь» (если tester что-то писал/менял).

## 3. reviewer (gate перед финальным `/commit`)

1. Спавни subagent `reviewer` (Agent tool, `subagent_type: "reviewer"`, foreground) с prompt: режим «код», диапазон диффа (от точки ветвления от `master` до текущего HEAD), пути к `spec.md`/`plan.md`/`constitution.md`.
2. `reviewer` вернёт находки через `ReportFindings`.
   - Пустой список → Definition of Done выполнено, переходи к шагу 4.
   - Есть находки → покажи их пользователю как есть (не исправляй молча). Спроси пользователя (`AskUserQuestion` в основном потоке): доработать (ещё один `developer`-раунд на конкретную находку + повторный `reviewer`, не более 2 циклов) / принять как есть с пометкой в `tasks.md` / остановиться. Без явного ответа пользователя — не двигайся дальше.

## 4. Definition of Done → финальный commit

Все три условия одновременно: все задачи `tasks.md` закрыты **и** `tester` подтвердил каждый `AC-N` **и** `reviewer` не имеет открытых находок (либо пользователь явно принял оставшиеся).

Только тогда — обычный `/commit` **без** аргумента «только закоммить»: мерж `feature/NNN-feature-name` в `master`, push, удаление ветки.
