**Ветка:** `feature/000-project-bootstrap` · **Источник:** `plan.md` + `spec.md` этой же фичи · **Автор роли:** architect

Каждая задача ссылается на конкретный `AC-N` из `spec.md`, который она закрывает. `[P]` — задача потенциально параллелизуема (в текущей версии `/implement` это не используется для реального параллелизма, задачи выполняются строго последовательно — маркер зарезервирован на будущее).

Вместо неё после реализации ядра идёт фаза «Verification» — ручная проверка по чеклисту `quickstart.md`, которая играет роль критерия готовности вместо автотестов. Порядок задач внутри Core соответствует зависимостям импортов, а не TDD.

## Фаза: Core

- [x] T004 [P] — Создать `src/render/canvas.ts`, экспортирующий `setupCanvas()`: получает/создаёт `<canvas>`, один раз при вызове выставляет `canvas.width = window.innerWidth` и `canvas.height = window.innerHeight` (буфер рисования, не только CSS-размер), возвращает `{ canvas, ctx }` (2D-контекст). Без обработчика `resize`. _(AC-2)_ — **Примечание:** получает элемент по `document.getElementById('game-canvas')`; если не найден — создаёт `<canvas id="game-canvas">` и добавляет в `document.body`. `getContext('2d')` может вернуть `null` (граница браузерного API) — в этом случае `throw new Error(...)`, это не лишняя валидация. `npx tsc --noEmit` — без ошибок.
- [x] T005 [P] — Создать/переписать `src/style.css`: `html, body { margin: 0; }`, `canvas { display: block; }` — убрать скроллбары и отступы браузера по умолчанию. Удалить неиспользуемые стили из дефолтного шаблона Vite (логотип, счётчик кликов и т.п.). _(AC-2)_ — **Примечание:** дополнительно добавлен `overflow: hidden` на `html, body`, чтобы гарантированно не появлялись скроллбары при canvas на весь viewport (в дополнение к минимуму из `plan.md`). Все шрифтовые/цветовые/демо-стили шаблона Vite удалены; `body { margin: 0 }` из старого файла консолидирован в новое правило.
- [x] T006 [P] — Создать `src/game/loop.ts`, экспортирующий `createGameLoop(callback: (deltaTimeSeconds: number) => void): { start(): void }`: замыкание с `lastTimestamp`, на каждый тик `requestAnimationFrame` вычисляет `deltaTime = lastTimestamp === null ? 0 : (timestamp - lastTimestamp) / 1000` (секунды, не мс), вызывает `callback(deltaTime)`. Никаких захардкоженных констант вида «16.6 мс» или «1/60». `deltaTime` передаётся как примитив `number`, не оборачивается в объект. _(AC-4, AC-5)_ — **Примечание:** реализация точно по формуле из `plan.md`; `start()` планирует первый `requestAnimationFrame(tick)`, `tick` сам себя переplanирует рекурсивно. В этой фиче нет тестового раннера (решение В2, «Не-цели» spec.md) — модуль остаётся чистой функцией без побочных эффектов на верхнем уровне для будущей тестируемости, автотест не писался, проверка — `npx tsc --noEmit` (без ошибок) и последующая ручная верификация по `quickstart.md` в фазе Verification. `npx tsc --noEmit` — без ошибок.
- [x] T007 [P] — Создать `src/dev/fpsCounter.ts`, экспортирующий `createFpsCounter(): { report(deltaTimeSeconds: number): void }`: считает количество кадров за последнюю секунду, обновляет текст в `<div>`-оверлее (`position: fixed`, минимальные инлайн-стили, без отдельного CSS-файла), добавленном в DOM при вызове `createFpsCounter()`. _(AC-4)_ — **Примечание:** алгоритм — не скользящее окно, а последовательные неперекрывающиеся интервалы: `report()` накапливает `frameCount` и `elapsedSeconds` (сумма переданных `deltaTimeSeconds`); при достижении `elapsedSeconds >= 1` текст оверлея обновляется на `frameCount`, оба счётчика сбрасываются в 0. Оверлей — `<div>` с инлайн-стилями (`position: fixed`, левый верхний угол, полупрозрачный чёрный фон, зелёный моноширинный текст, `pointer-events: none`), добавлен в `document.body` при вызове `createFpsCounter()`. Тестового раннера в этой фиче нет (решение В2) — проверка через `npx tsc --noEmit` (без ошибок), поведенческая проверка — в фазе Verification по `quickstart.md`. `npx tsc --noEmit` — без ошибок.

*(T004–T007 — независимые модули без взаимных импортов, могут вестись в любом порядке.)*
